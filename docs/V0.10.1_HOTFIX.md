## 1. Executive Summary & Root Cause Analysis

During initial dogfooding of AstraRun v0.10.1 on the physical host workstation, pressing `Alt+Space` caused the command bar to render momentarily and vanish in under 100ms.

Investigation with microsecond-level Win32 and Qt event tracing (`scripts/reproduce_launcher_lifecycle.py`) revealed four converging root causes:

### 1.1 Root Cause A: Naive Focus-Loss Dismissal Loop
In `LauncherWindow.changeEvent`, the window reacted to `QEvent.Type.ActivationChange` by immediately calling `self.dismiss_animated()` whenever `not self.isActiveWindow()`.
Because Windows 11 emits transient activation transitions during:
- Win32 `AttachThreadInput` / `SetForegroundWindow` handoffs,
- Initial top-level window mapping before focus stabilization,
- The physical release of the `Alt` key (`WM_KEYUP`), which triggers Win32 `SC_KEYMENU` / modal system menu tracking,
the launcher received a deactivation event within 50ms of appearing, instantaneously triggering its own exit animation.

### 1.2 Root Cause B: Win32 `SC_KEYMENU` System Command
Pressing and releasing `Alt+Space` sends `WM_SYSCOMMAND` with `wParam = SC_KEYMENU (0xF100)`. Windows shell interprets this as an instruction to enter the window's title bar system menu mode, briefly shifting modal focus away from the active child input control.

### 1.3 Root Cause C: Nested QGraphicsEffect Painter Collisions
`LauncherWindow` used a `QGraphicsOpacityEffect` animated via `QPropertyAnimation(opacity_effect, b"opacity")`, while child container `self.card` applied a `QGraphicsDropShadowEffect`.
In Qt 6 / PySide6, nested graphics effects on transparent frameless widgets cause recursive painter collisions:
```text
QPainter::begin: A paint device can only be painted by one painter at a time.
QWidgetEffectSourcePrivate::pixmap: Painter not active
```
This corrupted paint buffers, causing occasional blank frames and rendering aborts.

### 1.4 Root Cause D: Test Isolation Leak in Protected Window Registry
`LauncherWindow` and `FloatingTaskHUD` registered their HWNDs in `_ASTRARUN_HWNDS` (`astrarun.windows.policy`) to prevent self-manipulation. Under headless Qt (`-platform offscreen`), Qt allocates low synthetic window IDs (e.g., 20, 30). Because windows were not unregistering upon teardown, mock windows in subsequent tests were falsely classified as internal AstraRun windows and skipped.

## 2. Technical Architecture of the Fix

### 2.1 Explicit 6-State Lifecycle Machine (`LauncherState`)
The launcher lifecycle was redesigned from implicit boolean flags to an explicit Finite State Machine:

```text
       ┌──────────┐
       │  HIDDEN  │ ◄──────────────────────────┐
       └────┬─────┘                            │
            │ present_animated()               │
            ▼                                  │
       ┌──────────┐                            │
       │ ENTERING │ (150ms slide-in animation) │
       └────┬─────┘                            │
            │ entrance finished                │
            ▼                                  │
      ┌────────────┐                           │
      │ ACTIVATING │ (150ms grace period timer)│
      └─────┬──────┘                           │
            │ grace period elapsed             │ dismiss() /
            ▼                                  │ dismiss_animated()
     ┌─────────────┐                           │
     │ INTERACTIVE │ (User typing & input) ────┤
     └──────┬──────┘                           │
            │ Enter / action confirmed         │
            ▼                                  │
      ┌───────────┐                            │
      │SUBMITTING │ ───────────────────────────┤
      └─────┬─────┘                            │
            │                                  │
            ▼                                  │
       ┌──────────┐                            │
       │ EXITING  │ (110ms slide-out animation)│
       └────┬─────┘                            │
            └──────────────────────────────────┘
```

1. **`ENTERING` & `ACTIVATING` Protection**: While in `ENTERING` (150ms drop-in animation) and `ACTIVATING` (150ms post-entrance stabilization grace timer), ALL `WINDOW_DEACTIVATE` events are strictly ignored and logged as transient:
   ```python
   if self.state in (LauncherState.ENTERING, LauncherState.ACTIVATING):
       self._log_lifecycle("DISMISS_BLOCKED", reason=f"protected_in_{self.state.value.lower()}")
       super().changeEvent(event)
       return
   ```
2. **`INTERACTIVE` Focus Policy**: Even when interactive, focus loss alone does NOT dismiss the launcher unless `hide_on_focus_loss` is explicitly enabled in `config/settings.json` (default: `false` for daily-driver stability).
3. **Intentional Dismissals Only**: The launcher dismisses ONLY upon:
   - Explicit `Escape` key (`self.dismiss(reason="escape_key")`),
   - Direct `Alt+Space` hotkey toggle (`reason="toggle_visibility"`),
   - Valid command execution / confirmation (`reason="command_executed"`),
   - Fast-path execution (`reason="fast_path_executed"`).

### 2.2 Win32 `SC_KEYMENU` and `Key_Alt` Interception
- Intercepted in `nativeEvent()`:
  ```python
  if msg.message == WM_SYSCOMMAND and (msg.wParam & 0xFFF0) == SC_KEYMENU:
      self._log_lifecycle("SC_KEYMENU_SWALLOWED", extra="Alt_system_menu_blocked")
      return True, 0
  ```
- Swallowed in `keyPressEvent()` and `keyReleaseEvent()`: Releasing the `Alt` key after `Alt+Space` is consumed, preventing the Windows shell menu tracking loop.

### 2.3 Native `windowOpacity` Replacement
Removed `QGraphicsOpacityEffect` on `LauncherWindow`. Replaced with native Qt top-level window opacity:
```python
self.opacity_anim = QPropertyAnimation(self, b"windowOpacity")
```
This completely eliminates painter recursion errors (`QPainter::begin` conflicts) and ensures hardware-accelerated composition.

### 2.4 HWND Registration Teardown & Test Isolation
- Added `self._registered_hwnd` tracking and clean `closeEvent()` unregistration to both `LauncherWindow` and `FloatingTaskHUD`.
- Added autouse fixture `clean_astrarun_hwnds` in `tests/conftest.py` ensuring test isolation across all test suites.
