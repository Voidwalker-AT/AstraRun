## 1. Prime Security Invariants

All development in AstraRun v0.9 strictly preserves the foundational security principles of the platform:

1. **Zero Raw Shell Execution Invariant**:
   - AstraRun NEVER passes arbitrary user strings to `shell=True`, `os.system()`, `eval()`, `exec()`, or PowerShell `Invoke-Expression`.
   - Every request is parsed into structured intent tokens, mapped to strictly typed capabilities, vetted by ActionGate, and invoked via parameter-checked native Python functions.
2. **Zero False Execution Rate (0.00% FER)**:
   - Untrusted, ambiguous, or dangerous operations must never execute automatically.
3. **Unconfigured Reasoning Boundary**:
   - Complex non-deterministic queries escalate cleanly to the unconfigured AI Bridge interface without generating speculative local commands.
4. **Self-Targeting Immunity (`_ASTRARUN_HWNDS`)**:
   - AstraRun window handles are recorded upon creation. The window controller rejects any command attempting to minimize, snap, move, or close AstraRun's own resident interface.
5. **Time-of-Check to Time-of-Use (TOCTOU) Validation**:
   - Process termination and window manipulation verify process start time, executable identity, and PID before applying mutations.

## 2. Window Intelligence Security Boundaries (`policy.py`)

The Window Subsystem introduces specialized OS-level security boundaries:

### 2.1 Protected Shell Window Classes
Windows desktop shell infrastructure must remain completely untouched by tiling or close operations:
- `Shell_TrayWnd` (Windows Taskbar)
- `Shell_SecondaryTrayWnd` (Multi-monitor taskbars)
- `Progman` (Program Manager desktop surface)
- `WorkerW` (DWM desktop wallpaper layer)
- `Windows.UI.Core.CoreWindow` (Start menu, Action Center)

Attempting to target these windows immediately fails with `CapabilityResult.fail("Protected Windows shell classes cannot be modified.")`.

### 2.2 TOCTOU PID Mismatch Protection
Before restoring or moving a window from the undo stack, `validate_window_identity()` checks:
```python
current_pid = user32.GetWindowThreadProcessId(hwnd, None)
if current_pid != snapshot.pid:
    return False  # Target process terminated and HWND was recycled
```
This eliminates the race condition where an application closes and a different application receives the recycled HWND.

### 2.3 Safe Window Termination
- Window closing is implemented via `PostMessageW(hwnd, WM_CLOSE, 0, 0)`.
- It NEVER invokes `TerminateProcess` or `taskkill /F`.
- This ensures applications perform their standard Win32 shutdown protocol, giving users the opportunity to save unsaved documents.
