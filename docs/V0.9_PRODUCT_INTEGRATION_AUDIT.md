# AstraRun v0.9 Product Integration Audit

> **Date**: 2026-09-27  
> **Status**: COMPLETED AUDIT  
> **Target**: Comprehensive assessment of UI reachability and daily workstation usability across all v0.1–v0.8.5 subsystems.  

---

## 1. Executive Summary

AstraRun has constructed 16 distinct subsystems across v0.1 to v0.8.5 with outstanding benchmark guarantees (100% accuracy, 0.00% False Execution Rate, 215 passing unit tests). 

However, an audit of the real application entry point (`src/astrarun/main.py`) and UI window (`src/astrarun/ui/launcher.py`) reveals a critical architectural gap:

> [!CAUTION]
> **The Real UI is Stuck at v0.2**:  
> `src/astrarun/main.py` still loads only the legacy v0.1/v0.2 `DeterministicRouter` and legacy `ToolRegistry` (handling only basic `open_app`, `open_folder`, `open_url`).
> **Fourteen out of sixteen major subsystems are completely disconnected from the resident UI hot path (`Alt+Space`)**.

When a user summons AstraRun via `Alt+Space` and types `"system status"`, `"what's using port 3000?"`, or `"history"`, the application fails with `"Unknown command"` because the request is never routed to the Hybrid NLP Engine, Entity Resolver, ActionGate, TaskManager, or Capability Registry.

## 4. Audit of Launcher User Input Flow (`src/astrarun/ui/launcher.py`)

When the user types a query in `LauncherWindow` and presses `Enter`:
1. `LauncherWindow.execute_command()` checks if a suggestion is highlighted in `suggestions_list`. If so, it calls `_execute_result(res)`.
2. Otherwise, it calls `decision = self.router.route(query, self.context)`.
3. `DeterministicRouter.route(query)` only recognizes:
   - Prefix commands: `open <app>`, `launch <app>`, `start <app>`, `show <folder>`, `go to <url>`
   - Exact/fuzzy app names in discovery cache
   - Web URLs and folder paths
4. If the query is anything else (e.g. `"system status"`, `"what is running on port 3000"`, `"open latest screenshot"`, `"focus chrome"`):
   - `DeterministicRouter` returns `Decision(tool="unknown")`.
   - `self.registry.execute(decision)` rejects it with: `"Unknown command. Type an application name, folder, or search query."`
   - Launcher displays error in red label.

## 5. Architectural Remediation Plan for v0.9

To make AstraRun a genuine daily driver, we must:

1. **Create an Application Composition Root (`src/astrarun/app.py` -> `AstraApplication`)**:
   - Centralizes the instantiation, dependency injection, and clean shutdown of all subsystems.
   - Instantiates `ContextEngine`, `ProjectRegistry`, `CapabilityRegistry`, `EntityResolver`, `ActionGate`, `TaskManager`, `TaskLedger`, `TaskEventBus`, `LearningEngine`, `MemoryStore`, `AliasManager`, `WorkflowEngine`, and `ObservationStore`.

2. **Establish the Canonical Committed-Request Pipeline**:
   - Fast Path: Instant deterministic match for exact launcher actions (0ms overhead).
   - Rich Path: Unresolved or natural language queries enter `TaskManager.create_task()` ➔ `HybridNLPEngine` ➔ `StructuredUtterance` ➔ `EntityResolver` ➔ `WorkflowCompiler` ➔ `ActionGate` ➔ `CapabilityRegistry / WorkflowEngine` ➔ `TaskEvents` ➔ Rich Result UI ➔ `TaskLedger` ➔ `LearningEngine`.

3. **Expand Launcher Window to Multi-View Mode**:
   - `Compact Command Bar`: The default sleek bar.
   - `Activity View`: Shows live `TaskActivityView` during multi-step execution.
   - `Result Cards`: Displays `ResultCard` / `ListResultCard` for information queries.
   - `Confirmation / Disambiguation Cards`: Keyboard-interactive safety gating.
   - `Full Panels`: Modal/split views for `HistoryView`, `MemoryView`, `SkillReviewWidget`, and `Settings`.

4. **Add Daily Driver Operating Controls**:
   - Commands: `history`, `memory`, `skills`, `settings`, `help`, `what can you do?`, `diagnostics`.
   - Windows System Tray (`QSystemTrayIcon`) with clean menu and single-instance lock.
   - Origin-window capture on `Alt+Space` activation so `"this window"` refers to the user's active window before summoning Astra.

5. **Implement Window Intelligence Subsystem (`src/astrarun/windows/`)**:
   - Direct Win32 window and monitor manipulation, layout engine (snap, tile), and bounded undo stack.
