# AstraRun v0.10.2 Product Reality Audit

> **Target Incident**: Physical Workstation Test Failure (`open notepad and type pqr`)  
> **Initial Observed Result**: ✓ Notepad opened, ✗ "pqr" was NOT typed  
> **Milestone**: v0.10.2 Resolution Audit  
> **Status**: RESOLVED & EMPIRICALLY CONFIRMED  
> **Date**: 2026-09-28  

---

## 1. The Incident

During physical workstation validation of AstraRun following the v0.10.1 launcher hotfix, the user pressed `Alt+Space`, typed:

```text
open notepad and type pqr
```

and pressed Enter.

### Observed Behavior
1. Modern Windows 11 Notepad opened.
2. The text `"pqr"` was **not typed** into the document.
3. AstraRun closed its command bar and reported successful launch of Notepad.

### Immediate Impact
AstraRun was functioning only as an application launcher rather than an intelligent workstation operator capable of natural-language execution.

---

## 2. Root Cause Forensic Analysis

A rigorous forensic audit of the event sequence revealed three separate compounding bottlenecks:

### Root Cause 1: Launcher Autocomplete Hijacking
In `LauncherWindow._on_text_changed()`, as the user typed `"open notepad and type pqr"`, the search backend fuzzy-matched `"notepad"`. The UI created a suggestion list and pre-selected index 0 (`"Notepad"`).
When the user pressed `Enter`:
```python
# PREVIOUS BUGGY BEHAVIOR:
if self.suggestions_list.count() > 0 and self.suggestions_list.currentRow() >= 0:
    self._execute_suggestion(self.suggestions_list.currentItem())  # -> Executed "open notepad"!
```
The entire rest of the sentence (`"and type pqr"`) was discarded.

### Root Cause 2: Asynchronous App Launch Race Condition
Even if the compound string had bypassed the suggestion list, modern Windows 11 Notepad is an MSIX packaged application (`Microsoft.WindowsNotepad_8wekyb3d8bbwe`) running with XAML Islands UI (`RichEditD2DPT`).
Spawning `notepad.exe` returns control to Python immediately. Keystrokes fired immediately after spawn were lost into the void because:
1. The top-level `HWND` did not yet exist.
2. The interactive message pump of Notepad was still initializing.
3. The XAML document element had not yet been attached to the accessibility tree.

### Root Cause 3: Win32 Foreground Lock Restrictions
On Windows 10/11, background processes and non-interactive sessions cannot arbitrarily steal focus or inject keystrokes into other applications due to `LockSetForegroundWindow`. The previous foreground activation logic did not attach to the interactive input desktop (`OpenInputDesktop`) and failed to break the foreground lock via `AttachThreadInput` / Alt-key pulse.

## 3. The v0.10.2 Solution Architecture

| Layer | Previous (v0.10.1) | Solution (v0.10.2) |
| :--- | :--- | :--- |
| **Launcher UI** | Autocomplete suggestions remained visible; Enter executed selected item | `has_compound_indicators()` suppresses suggestions for compound queries; Enter dispatches raw literal text |
| **NLP & Routing** | Router attempted single-capability dispatch | Compound queries bypass single-app fast path and are routed directly to `WorkflowCompiler` |
| **Workflow Plan** | Unsynchronized 2-step plan (`open_app` + `type_text`) | **Synchronized 4-step plan**: `open_application` -> `wait_for_window` -> `resolve_editable_element` -> `type_text` |
| **State Propagation** | Steps ran statelessly with no handle passing | `WorkflowContext` carries `app`, `hwnd`, and `target_element` across all steps |
| **Desktop Attachment** | Attached to non-interactive thread desktop | `_ensure_desktop_attached()` attaches to `OpenInputDesktop(0, False, 0x01FF)` |
| **Focus Activation** | Simple `SetForegroundWindow` (frequently blocked by OS) | `force_foreground_activation` uses `AttachThreadInput`, `AllowSetForegroundWindow(-1)`, and `VK_MENU` pulse |
| **Keystroke Delivery** | Unverified keystrokes into current focus | 6-point focus verification followed by Unicode `SendInput` into resolved `RichEditD2DPT` control |
| **Task Telemetry** | Hidden background task execution | `FloatingTaskHUD` displays non-activating passive progress: `Step 1/4` -> `Step 2/4` -> `Step 3/4` -> `Step 4/4` |
